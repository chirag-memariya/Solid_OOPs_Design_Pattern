# find customers who haven't ordered in the past 30 days( IMP: Real-word use of left join)
-- have never placed an order, or
-- have place orders but none within the last 30 days

select 
    c.customer_id, 
    c.customer_name,
    MAX(o.order_date) AS last_order_date 
from 
    customes c 
left join orders on c.customer_id = o.customer_id 
group by 
    c.customer_id,c.customer_name
        having last_order_date IS NULL OR last_order_date < DATE_SUB(CURDATE(), INTERVAL 30 DAY); 

note - 
Why MAX(o.order_date)?
Each customer may have multiple orders.
We only care about the latest order date.
MAX(o.order_date) gives us the most recent order per customer after grouping.

* for customer lets we have these two orders  
- order 1: placed 60 days ago
- order 2: placed 10 days ago, then these will delete if we use where as it applied before grouping,
                                --> so this will scan row by row and we have 60 days ago row not 10 days ago 
                                    which is latest and we want latest order should be greater than 30 days 
                                    then is will give 60 > 30 yes and wrong ans we need 10 > 30 and not include it to ans 
HAVING filters groups after aggregation.
First, SQL groups all orders per customer.
Then it calculates MAX(o.order_date) (the true last order).
Finally, HAVING checks if that last order is NULL (never ordered) or older than 30 days.

⚖️ Practical Effect in Your Case
If you write:

sql
select a.floor_number, count(a.apartment_id) as unoccupied_count
from apartments a
left join residents r on a.apartment_id = r.apartment_id
where r.resident_id is null
group by a.floor_number
having count(a.apartment_id) > 1;
The WHERE ensures only unoccupied apartments are grouped.

The HAVING ensures only floors with more than 1 unoccupied apartment appear in the result.

If you tried to use HAVING instead of WHERE for the r.resident_id is null condition, it would still work but less efficiently, because grouping would include all apartments first, and only then filter groups where the count of residents is zero.

📝 Rule of Thumb
Use WHERE for filtering raw rows.

Use HAVING for filtering aggregated/grouped results.

### FULL JOIN 
-- it return all matching rows from both tables where the join condition is met 
-- it also retual all non-matching rows from the left talbe (with null values for columns from the right table)
-- it also retual all non-matching rows from the right talbe (with null values for columns from the left table)

-- it combines the results of both left join and right join, including all records from both tables and matching records from both sides where available

-- example an "employee" table 
-- A "department" table 
-- all emplyee with their departments
-- all employees without departments(with null for department columns)
-- all departments without employees(with null for employee columns)

-- inner join (only return mathching row between talbes)
-- left join(returns all rows from left table and matching from right)
-- right join(returns all rows from right talbe and matching from left)
